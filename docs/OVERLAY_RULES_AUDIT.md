# Overlay and web app audit — 25 October 2026

Scope: current local source, the hosted demo linked in README, submission documents, and Microsoft's official hackathon rules. This is a review; application code was not changed.

Rules: https://github.com/microsoft/insidethegamehackathon/blob/main/OFFICIAL%20RULES.md and the local `OFFICIAL RULES.md`. Microsoft's raw rules were retrieved during this review. The shortened registration URL could not be retrieved by the web tool.

Rule interpretation: sections 4.3 and 4.8 require a consistently functioning, accessible project that matches the submission. Section 4.1 describes the challenge and expected experience; the optional feature examples are not separate mandatory features. Section 6.2 scores implementation, agentic design, impact, UX, and category adherence equally. Findings below distinguish defects from scoring weaknesses and unverified submission requirements. They are not a legal determination of eligibility.

Evidence: inspected the hosted UI, followed its replay to full time, read the frontend/backend and agent code, ran focused Python probes, and ran the full existing suite: **43 passed in 7.06 seconds**. The initial sandbox run could not create pytest temporary directories; the subsequent approved run outside the sandbox passed. Passing tests do not cover most defects below. Native Tauri execution, all languages, all screen sizes, and cloud infrastructure settings were not exhaustively tested.

## Fix first: correctness and the core challenge

1. **P1 — Goals air before the goal happens.** `match_intelligence.py:201` stores each goal's lead-up start as `timestep - 60`. `replay_server.py:300` publishes it at that start, and the displayed goal clock also reflects the start. Actual game 0 records: M0-0005 starts at 384 and ends at the score change at 444; M0-0010 is 973/1033; M0-0025 is 2641/2701. This announces the result 60 timesteps early, equivalent to 1:48 on the synthetic match clock. The scorebar uses the actual tracking score, so the goal cue and score can disagree. Add an explicit occurrence/availability time, separate from the evidence interval, and use it for airing, score, clock, and valuation. Relevant: 4.1 live synchronization, 4.3 functionality.

2. **P1 — Live statistics and narratives use future evidence.** `running_stats()` and `frame_at()` select rhythm windows at their start, even though the metrics summarize the entire window. The first window covers 0–149 but its possession share is already available at timestep 0. Pass completion, sprint totals, and build-up moments can likewise be scheduled from sequence starts before the sequence is complete. `get_moment_context()` explicitly supplies later events and an after-window; agent player profiles and recaps have no as-of boundary. In the hosted demo, a verified goal story referred to a subsequent momentum shift; another momentum story described a later goal. Enforce `available_at <= viewer_time` throughout tools, caches, agents, and rendering; give retrospective analysis a distinct mode.

3. **P1 — The evidence gate accepts fabricated claims.** A direct call with a real moment citation accepted `The referee awarded a penalty.` It also accepted `This shot was 1 km/h and chance probability is 0.9999.` `mcp_server.py:248` exempts numbers whose absolute value is <=1; the gate checks numerical membership rather than which player, metric, unit, team, or event a claim describes. `_supported_numbers()` additionally includes final score and full-match player statistics. Replace the bag-of-numbers check with structured claim-to-evidence validation and temporal checks. Until then, use an accurately limited badge such as “citation check passed,” and remove claims that every fact is verified.

4. **P1 — Checks do not reliably control what reaches the screen.** The server includes `validation` and `cue_validation` in outgoing data even when invalid; `routeCue()` and `airCue()` do not reject it. `cue_check()` returns no result for cues without moment/event citations, including recaps and distance milestones. It does not check supporting metrics. Block failed checks before publication; define validators and evidence references for derived metrics too. A producer override, if offered, needs to be explicit.

5. **P1 — The verified badge does not validate the text underneath it.** `enriched_overlay()` validates the overlay, but `enrich()` separately assigns `data.text` from personalized commentary or raw orchestrator text. `showEnriched()` labels the card verified using overlay validation while rendering `data.text`. `/api/ask` also sends failed validation results to the viewer with a warning instead of a safe fallback. Validate the final displayed text, not only its companion card. Discard or safely rewrite failed prose.

6. **P1 — The automatic full-time recap is not a match recap.** The `end` handler calls `askMatch(..., false)`, disabling the agent path. There is no recap action in `commentary.Action` or recap intent in `INTENTS`; the question becomes `explain_more`. A direct probe at timestep 2999 returned only Port Saltmere United's late goal and its lead-up. The hosted app did the same at full time. Implement a dedicated as-of recap with result, turning points, both teams, standout players, and supporting evidence. Manual Recap also needs this deterministic behavior when AI is disabled or unavailable. Relevant: 4.1 narrative generation.

7. **P1 — The new interest dials are discarded by the AI orchestrator.** The replay server sends `interests`, but `agents/orchestrator/main.py:27–42` only retains keys in `DEFAULT_PROFILE`, which lacks that field. Local cue filtering works, but automatic AI personalization loses these preferences. Pass a shared, validated profile contract through the orchestrator and specialists. Also preserve meaningful newcomer/money differences: `agent_profile()` currently collapses them to casual.

8. **P1 — Language selection applies only to part of the experience.** `instant_overlay()` hardcodes English; deterministic cue explanations, commentary, quick replies, splashes, and value content are English. `commentary.respond()` does not use `prefs.language`. Changing the language clears the feed and changes its language badge, although immediate content remains English; fallback overlays can be English too. Localize the promised surfaces, identify fallback language honestly, and support RTL layout where needed. Nine selectable languages currently imply more coverage than the code provides.

9. **P1 — The public demo and local app are different versions.** The hosted page showed Viewer and Focus menus plus “How do you watch?” onboarding; the local app has five interest dials and “What do you care about?” onboarding. Judges testing the public URL cannot assess the local feature set. Deploy one reviewed revision, invalidate incompatible caches, expose a version/build identifier, and record that revision in the submission. Relevant: 4.3 and 4.8.

## Functionality, personalization, and broadcast operation

10. **P2 — Casual narration is still technical output.** Observed hosted casual cards contained `possession_share_team0`, `momentum_before`, `PLAYER_ID`, event IDs, decimal fractions, and long event chains. These are difficult to absorb alongside a match. Produce short audience-specific copy, convert shares to understandable percentages, name players, and put technical evidence behind a disclosure. Show the same moment in casual and analyst modes to demonstrate a substantive difference.

11. **P2 — Heuristic confidence is presented as a probability.** `CONFIDENCE` converts HIGH/MEDIUM/LOW into 90%/70%/45%, and other derived facts default to 80%; goals get at least 95%. README correctly says these are uncalibrated heuristics. UI percentages suggest calibrated certainty. Use qualitative labels with their basis, or calibrate the values; distinguish certainty that the score changed from uncertainty about the scorer or preceding action.

12. **P2 — Several explanations assert more than the evidence supports.** `why_it_matters()` says a shot tests the keeper, a difficult pass breaks a line, a turnover attacks an unset defence, and a sprint is among the fastest. Those conclusions do not follow automatically from shot candidacy, lane clearance, location, or an early sprint tag. “Distance to goal line” is also described as distance “out,” which can imply distance to goal. Restrict claims to measured predicates, compute the missing evidence, or clearly label interpretation.

13. **P2 — Favorite club barely changes deterministic output.** Local club selection dims opposition totals but does not prioritize club cues or change their explanation. The favorite club is unused by deterministic commentary. Add a meaningful club lens while keeping neutral match context. Relevant: 4.1 personalization.

14. **P2 — Player focus is mostly a highlight and one-off answer.** The radar circles the favorite and some moments gain priority, but there is no persistent player contribution panel or sustained player-focused narrative. Some threshold cues remain low priority and hidden at balanced depth. A selected player should have an ongoing as-of contribution view and clear behavior during quiet spells or substitutions.

15. **P2 — Player ID 0 is lost by truthiness checks.** The UI passes `Number(player.value) || null`; Python focus routing also uses `or` for IDs. ID 0 is a valid roster player. Use explicit null/empty checks throughout selection, question parsing, and feedback.

16. **P2 — “Focus on [name]” can focus someone else.** The quick reply is generated from the moment's player, but the click handler supplies `state.last.player_id`, which is often null on ordinary explanations, rather than the player named in the reply. A preselected favorite can win that fallback. Send structured actions containing the actual player ID.

17. **P2 — Feedback does not consistently affect subsequent automatic commentary.** Depth filters cue priorities locally; tone/tactical preferences reach the Ask request, but automatic stream/enrichment profiles omit them. “More emotional” or “More tactical” therefore does not establish the promised persistent live experience. Pass these preferences through the same profile contract and cache key as other personalization.

18. **P2 — Some preferences disappear on reload.** Dials/depth/tone are saved, but language, club, and player are read from selects and are not restored by `init()`. Persist and restore all promised viewer preferences, validating old stored values.

19. **P2 — Changing controls can resume a paused replay.** Every control change reconnects immediately, even when `state.paused` is true; Restart also reconnects without resetting that flag or the Resume label. Keep paused state authoritative and defer reconnection until Resume, or explicitly reset it on Restart.

20. **P2 — Reconnection mixes old and new UI state.** `connect()` clears feed entries and queued alerts but does not cancel the active alert timer, reset `alertBusy`, clear all moment context, invalidate outstanding Ask/value requests, or cancel splash sequences. A preference change or game switch can leave an old cue/answer visible or let a late response overwrite the new game. Use a session generation/abort controller for every asynchronous path and reset all session state together. `askToken` protects deterministic commentary, but `ask()` has no equivalent response check.

21. **P2 — Player value selection can ignore the latest choice.** `loadValue()` returns immediately while busy, dropping a selection change, and applies a response without checking the current game/player/session. Queue the latest selection or cancel the prior request and only commit matching responses.

22. **P2 — The producer queue does not control a shared broadcast output.** It is client-local state. Two tabs have independent streams and controls; On air does not control other viewers, clear already queued alerts, or suppress the AI feed. Manual Air is not gated by the on-air checkbox or minimum confidence. Define the switch's semantics, separate preview from program, enforce checks at the publication boundary, and use shared server-side cue state if claiming a broadcast control room. The current UI can still be described honestly as a local producer preview.

23. **P2 — Desktop producer controls are outside the click target map.** Tauri only accepts mouse interaction inside `[data-hit]` rectangles. The `#studio` section lacks that attribute, so its Air/Drop and filtering controls pass clicks through. Include the producer section and test native interaction.

24. **P2 — The desktop package depends on a manually started Python service.** Tauri loads static UI and always calls `127.0.0.1:8765`; no bundled sidecar or automatic backend startup is configured. A judge installing only the NSIS package cannot run the advertised experience. Provide and test a complete installer/start procedure, or clearly submit the hosted web app as the supported judging platform. Verify first-run failure and recovery on a clean machine.

25. **P2 — Replay has no external feed synchronization.** SSE is driven by an independent local playback position, not a match video's timebase; there is no video binding, seek control, or sync offset. A transparent window alone cannot synchronize to arbitrary footage. Demonstrate it over a rights-cleared synthetic animation with shared timing, or scope the claim to the self-contained radar replay. Video auto-eventing is an optional example in 4.1, not a mandatory missing feature.

## Reliability, data realism, and UX

26. **P2 — Live AI latency and cache coverage need honest handling.** Hosted cards displayed recorded agent traces around 35–92 seconds, often cached. Those traces are not measurements of current delivery latency; nevertheless uncached work has multi-stage calls, retries and no replay-level deadline. User-specific profiles multiply cache keys. Show actual delivery age, expire late insights, provide immediate grounded fallback, and measure cold/warm p50/p95 latency. Cache identity must include data/model/prompt/schema version, not just match/moment/profile.

27. **P2 — Public requests can consume the shared AI allowance and leave orphaned work.** `/api/ask` has no per-viewer limit and bypasses the enrichment semaphore. Every SSE connection can schedule enrichment; a cache miss is checked before the semaphore without single-flight protection. Disconnecting leaves tasks in the global `background` set, doing work for a vanished viewer. The allowance is process-local and resets per worker/restart. Bound concurrency, deduplicate work, cancel unneeded tasks, add fair request quotas, and keep baseline judging functionality available when the AI budget is spent.

28. **P2 — API validation and recovery are incomplete.** Game/player IDs and numeric values are converted directly, games are indexed without validation, malformed JSON is not handled consistently, and profile values are only partially checked. Bad requests can produce internal errors. If `/api/meta` fails, `init()` returns before registering most UI handlers, leaving no in-app retry. Use validated request models, useful 4xx responses, a ready/health endpoint, and a working retry path. Invalid-input behavior was established from source; the full expensive cold-start API probe was stopped and is not counted as a completed runtime test.

29. **P2 — Warm-up can block replay responsiveness.** The first load parses both complete tracking CSVs and constructs arrays for all matches. Stream setup synchronously builds derived and money cues before sending its first event. Value-board generation repeatedly computes per-player values and peer statistics. Expensive synchronous work inside async routes can stall other viewers. Precompute immutable data, expose warm-up state, and move remaining CPU work off the request event loop; benchmark on the deployed resource limits.

30. **P2 — The synthetic extension is only partly integrated and is not a coherent simulated world.** Tackle/pressure rows feed valuation, but replay/MCP tables do not ingest the extra event/meta/substitution files. Substitutions are generated independently; the tracking roster, event actors and value board do not follow an active-lineup timeline. A substituted player can continue accumulating actions while the replacement never appears in tracking; the board excludes bench players permanently. Apply a single roster/time/state model and validate event-location, actor and substitution consistency before presenting this as football-realistic data innovation.

31. **P2 — The money model needs stronger qualification and correct timing.** Wages are prorated from one weekly wage across one match, with a minimum 20% charge from the start; hard-coded action awards drive “bargain/overpaid” labels. `_shots_faced()` treats non-scoring candidate shots as goalkeeper credit and looks forward for goals, without filtering the matched goal by scoring team. Goal value also uses the early lead-up start. Correct occurrence/as-of timing and goalkeeper attribution; explain that these are chosen illustrative scoring rules rather than measured economic worth. Synthetic labeling already exists and should be retained.

32. **P2 — Time and speed have incompatible implied scales.** `match_clock()` stretches 3000 timesteps into 90 minutes (1.8 displayed seconds per timestep); physical speeds assume 0.1 seconds per timestep, inferred rather than sourced. This can be intentional synthetic compression, but the UI presents the clock and km/h side by side without explaining it. Explicitly label the normalized clock and estimated physical timing, and use one documented timing contract for speeds, distances, replay multipliers and availability.

33. **P2 — Accessibility has functional gaps.** Collapsed panels use opacity/grid collapse without `hidden`/`inert`, so hidden controls remain in the accessibility tree and can remain keyboard-focusable. The onboarding dialog has no focus trap, initial focus, or focus restoration; the question field has no persistent label. The live score region includes a rapidly changing clock, and animated word spans can make announcements noisy. Add proper disclosure/modal behavior, a question label, restrained live announcements and a textual alternative to essential radar information. Native click-through also needs keyboard navigation testing.

34. **P2 — The interface does not reliably protect match visibility or reading time.** Desktop panels and bottom tiles occupy independently fixed areas; feed overflow is hidden with no history control. On narrow layouts the radar precedes Ask/Match centre in a long vertical page, and the producer section has separate sizing. Compact chips omit explanation/confidence, expire quickly, and cannot be reopened. Auto full-time commentary opens Ask and changes the current panel. Provide readable cue history, safe layout zones, responsive access to primary controls, and non-disruptive recap delivery. These are source-backed UX risks; this review did not complete a viewport matrix or native visual test.

35. **P2 — Session splashes can overlap or outlive the session.** `sequence()` has no cancellation token; reconnect/restart does not stop it. Kick off uses `splash()` directly, so it does not set the same busy guard as half/full time and can be replaced by a theme sting. Half-time also does not pause replay. Guard transition ownership, cancel old sequences, and derive match phases from explicit match metadata rather than only clock thresholds.

36. **P2 — Test coverage and submission claims are out of step.** The 43 passing tests are useful unit coverage but do not prove browser flows, native installation, causal/as-of boundaries, all language surfaces, session races, or a shared producer output. The manual checklist is unticked. `VIDEO_OUTLINE.md` still describes different agent roles in shot 8, then corrects itself in a later note; `PITCH.md` and the checklist call the existing synthetic extension pending/untracked. README contains conflicting statements about availability of physical speed. Update these documents to the exact shipped behavior, test the first minute and full-time flow on a clean browser, and add regression coverage for the P1 defects. Tauri CSP is also explicitly disabled; establish a restrictive policy before positioning it as enterprise-ready.

## Suggested repair sequence

1. Establish causal timestamps and fix early goals, future windows, future agent context and derived values.
2. Make every publication path enforce validation of the actual displayed content; remove overstated verification badges.
3. Build the real recap and propagate one complete viewer profile through all deterministic and agent paths.
4. Repair pause/reconnect/request races, native producer hit regions, and install/start/retry behavior.
5. Deploy the reviewed revision, invalidate incompatible caches, and verify cold/warm behavior with the AI allowance exhausted as well as available.
6. Localize or narrow the language promise; make casual/analyst/favorite experiences visibly different; finish accessibility and reading-history fixes.
7. Align synthetic lineup/state and metric disclosures, then record a truthful demo and complete external submission checks.

Already present: synthetic match data, fictional roster labeling, a functioning hosted replay, timed machine-readable cues, explainability templates, real Foundry/Agent Framework specialist orchestration, MCP tools, fallbacks, personalization controls, and a producer preview. The repair priorities concern their correctness and completeness; rebuilding everything is unnecessary.
