# JSON schemas

The schemas in `schemas/` describe the JSON that crosses the boundaries between the analytics code, the replay server, the overlay UI and the agents. All data is synthetic and the clubs and players are fictional (Kestrel Vale FC, Port Saltmere United).

## Schema files

| File | Title in file | Purpose |
| --- | --- | --- |
| `schemas/overlay_cue.schema.json` | `OverlayCue` | One broadcast cue for the overlay: insight, why it matters, confidence, evidence, priority, theme, duration, and supporting metrics and source event ids. Produced by `src/football_analytics/overlay_cues.py`. |
| `schemas/commentary_response.schema.json` | `CommentaryResponse` | The answer to an Ask the Match request: headline, observed facts, interpretation, optional projection, context trail, quick replies, depth and tone. `action: "recap"` gives a whole-match recap (score, scorers, key moments from both halves, team stats) as of the timestep. Produced by `src/football_analytics/commentary.py`. |
| `schemas/viewer_preferences.schema.json` | `ViewerPreferences` | The viewer's saved choices: persona (derived from interests), language, favourite club and player, per-stat interests (0-100), depth, tone and tactical flag. Used by `commentary.py`. |
| `schemas/feedback_event.schema.json` | `FeedbackEvent` | A feedback click (for example "Too basic") tied to a game, timestep and response. `apply_feedback` in `commentary.py` turns it into updated preferences and effect notes. |

The files do not carry a `description` field. The purposes above come from the file titles and the Pydantic models named in each row. Each schema has `schema_version` fixed to `"1.0"`. Tests in `tests/test_commentary.py` (`test_schemas_match_models`) and `tests/test_overlay_cues.py` (`test_schema_file_matches_model`) compare the schema files with the models.

## Example instances

The examples below were generated by running the repo's own Pydantic models and functions with `.venv-local\Scripts\python.exe` and `PYTHONIOENCODING=utf-8`. The commands used were:

- `football_analytics.commentary.respond(0, 2700, ViewerPreferences(depth="deep"), stats, "explain_more")` with `stats = {"possession": [60, 40], "ball_wins": [3, 2], "shots": [2, 1]}`, for the `CommentaryResponse` example.
- `ViewerPreferences(depth="deep")`, for the `ViewerPreferences` example.
- `FeedbackEvent(kind="too_basic", game_id=0, timestep=2700, response_id=<response_id from the CommentaryResponse above>)`, for the `FeedbackEvent` example.
- `football_analytics.replay_server.instant_overlay(replay_server.moments(0)[0])["cue"]`, for the `OverlayCue` example. This is the first key moment of game 0 as the replay server turns it into a cue.

Nothing in the four examples was hand-edited. All four are generated.

## Notes

- The `CommentaryResponse` example has `"synthetic": true`. The model fixes this field to `true`, so every commentary response carries the synthetic label.
- The `OverlayCue` example uses `evidence: "derived"` and an empty `source_event_ids`. That is what the replay server produced for this moment, not a trimmed value.
- The `CommentaryResponse` text is generated from the match data by `respond()`. This document did not separately check each sentence against the cited event ids.
